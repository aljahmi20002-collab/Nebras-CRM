# NebrasCRM — التطبيقات
**نسخة سطح المكتب · تطبيق الجوال · تطبيق الويب التقدمي**

---

## الفلسفة المعمارية

التطبيقات الثلاثة **غلاف أصلي حول نفس الخادم**، وليست نسخاً منفصلة من الواجهة.
هذا قرار متعمّد: كل ميزة تُضاف للنظام تظهر فوراً في كل المنصات دون إعادة بناء،
ولا تتفرّع الشيفرة فتختلف الإصدارات.

```
                    ┌─────────────────┐
                    │  خادم NebrasCRM  │
                    │  FastAPI + SQLite│
                    └────────┬────────┘
             ┌───────────────┼───────────────┐
       ┌─────▼─────┐   ┌─────▼─────┐   ┌─────▼─────┐
       │  المتصفح   │   │  Electron │   │ Capacitor │
       │   (PWA)   │   │  (سطح مكتب)│   │  (جوال)   │
       └───────────┘   └───────────┘   └───────────┘
```

## 1. تطبيق الويب التقدمي (PWA)

يعمل **فوراً بدون تثبيت أي شيء** — افتح `/app` في أي متصفح حديث واختر «تثبيت التطبيق».

### ما الذي يجعله تطبيقاً حقيقياً لا مجرد صفحة؟

| القدرة | التفصيل |
|---|---|
| **عمل دون اتصال** | 12 ملفاً أساسياً مخزّناً مسبقاً + نسخة من بيانات القراءة |
| **طابور الكتابة** | التعديلات دون اتصال تُحفظ في IndexedDB وتُرسل تلقائياً عند عودة الشبكة |
| **تحديث ذكي** | شريط «يتوفر إصدار جديد» — لا يُفرض التحديث حتى لا تضيع بيانات النماذج |
| **إشعارات Push** | مع أيقونة العلامة واتجاه RTL |
| **اختصارات** | 4 اختصارات من أيقونة التطبيق (اللوحة · الذكاء · العملاء · الشركاء) |

### استراتيجية التخزين

قُسّمت عمداً حسب نوع المحتوى، لأن لكل نوع خطراً مختلفاً:

- **هيكل التطبيق** (html/css/js/خطوط) → `cache-first` — إقلاع فوري.
- **بيانات القراءة** (`/api/**`) → `network-first` مع نسخة احتياطية — المندوب في منطقة بلا تغطية يرى خط مبيعاته.
- **عمليات الكتابة** → محاولة الشبكة، وإلا **طابور IndexedDB** يُعاد إرساله.

> **ملاحظة أمنية:** طلبات المصادقة **لا تُخزَّن ولا تُوضع في الطابور** إطلاقاً — تسجيل دخول مؤجّل خطر أمني، والرمز قد ينتهي قبل الإرسال.

الطابور يحذف العمليات التي يرفضها الخادم بخطأ 4xx، لأن إعادة محاولتها للأبد لن تنجح أبداً وستملأ الطابور.

## 2. نسخة سطح المكتب (Electron)

### التثبيت

| النظام | الملف |
|---|---|
| **Linux** | `NebrasCRM-1.0.0-x86_64.AppImage` (محمول) · `NebrasCRM-1.0.0-amd64.deb` |
| **Windows** | `npm run dist:win` → مثبّت NSIS (x64 + ARM64) |
| **macOS** | `npm run dist:mac` → DMG (Intel + Apple Silicon) |

```bash
# Linux — تشغيل مباشر بلا تثبيت
chmod +x NebrasCRM-1.0.0-x86_64.AppImage && ./NebrasCRM-1.0.0-x86_64.AppImage

# Debian / Ubuntu
sudo dpkg -i NebrasCRM-1.0.0-amd64.deb
```

### الميزات الأصلية

- **قوائم نظام كاملة** بالعربية والإنجليزية مع اختصارات لوحة المفاتيح
- **أيقونة شريط المهام (Tray)** — التطبيق يبقى يعمل بالخلفية عند الإغلاق
- **اختصار عام** `Ctrl+Shift+N` لإظهار/إخفاء النافذة من أي مكان
- **شاشة بدء** بالشعار المتحرك
- **إعدادات الخادم** — كل مؤسسة تستضيف نظامها، فالعنوان قابل للتغيير مع زر اختبار الاتصال
- **حفظ أبعاد النافذة** ومستوى التكبير بين الجلسات
- **إعادة الاتصال بعد استيقاظ الجهاز** — الجلسات تتعطّل بعد السبات

### الأمن

الغلاف يحمّل محتوى بعيداً، لذا الأمن ليس اختيارياً:

```js
contextIsolation: true      // عزل كامل بين الصفحة و Node
nodeIntegration: false      // لا وصول لـ Node من الصفحة
webSecurity: true
```

- **قائمة تنقل بيضاء**: أي رابط خارج نطاق الخادم يُفتح في المتصفح لا داخل التطبيق
- **رفض الأذونات افتراضياً** عدا الإشعارات والحافظة
- **منع `webview`** نهائياً حتى لا يُنشئ محتوى بعيد إطاراً بصلاحيات Node
- **الجسر (`preload`)** يكشف أفعالاً محددة فقط — لا IPC خام ولا نظام ملفات

### البناء

```bash
cd desktop && npm install
npm start            # تشغيل للتطوير
npm run dist:linux   # AppImage + deb + rpm
npm run dist:win     # مثبّت ويندوز
npm run dist:mac     # DMG
```

## 3. تطبيق الجوال (Capacitor)

| المنصة | الملف |
|---|---|
| **Android** | `NebrasCRM-1.0.0.apk` (موقّع للإصدار) |
| **iOS** | `npx cap add ios` ثم البناء عبر Xcode |

### الميزات

- **شاشة اتصال ذكية**: يُدخل المستخدم عنوان خادم مؤسسته مرة واحدة، ويُحفظ آخر 4 خوادم
- **أيقونة تكيّفية (Adaptive Icon)** — الشعلة داخل منطقة آمنة فلا تُقص بأي شكل قناع
- **اسم عربي على الشاشة الرئيسية**: «نبراس» عبر `values-ar/strings.xml`
- **دعم RTL أصلي** على مستوى النظام
- **زر الرجوع** يتنقّل داخل النظام ولا يُغلق التطبيق فوراً
- **`usesCleartextTraffic`** مفعّل لأن كثيراً من المؤسسات تستضيف داخلياً على HTTP

### البناء

```bash
cd mobile && npm install
npx cap sync android
cd android && ./gradlew assembleRelease
```

> **مفتاح التوقيع:** المرفق للتجربة فقط. أنشئ مفتاحك الخاص قبل النشر على المتجر
> واحفظه خارج المستودع — فقدانه يعني استحالة تحديث التطبيق على Google Play.

## لماذا حجم تطبيق الجوال 4 ميجابايت فقط؟

لأنه غلاف حول الخادم لا نسخة من الواجهة. الفائدة عملية: **تحديث النظام لا يتطلب
تحديث التطبيق على المتجر** — يكفي تحديث الخادم فيرى كل المستخدمين الإصدار الجديد فوراً.
هذا مهم في السوق المحلي حيث تحديثات المتاجر بطيئة وشبكات الإنترنت محدودة.

المقابل أن التطبيق يحتاج اتصالاً بالخادم للعمل الكامل — وهو ما يعالجه
تخزين PWA المؤقت وطابور العمليات دون اتصال.
